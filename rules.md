# Правила архитектуры и разработки Lime-Frog

## 1) Назначение документа

Этот документ фиксирует единый стандарт разработки проекта, чтобы новые вкладки (MVP-модули) добавлялись предсказуемо, без хаоса и без разрастания монолитного кода.

Главный принцип:

- `templates` — точка монтирования и общий каркас страницы.
- `tabs` — доменные модули (вкладки), где живет функциональность конкретного инструмента.

---

## 2) Текущая архитектурная модель (обязательная)

### 2.1 Роли папок

- `app.py`
	- Точка входа Flask-приложения.
	- Регистрирует API endpoints.
	- Отдает основной шаблон (`index.html`).
	- Настраивает загрузку шаблонов/статики для модулей.

- `templates/`
	- Общая оболочка интерфейса.
	- Содержит `index.html` (контейнер + общие модалки + подключение скриптов).
	- Может содержать только общие части, не привязанные к одной вкладке.

- `tabs/`
	- Место для модулей-вкладок.
	- Каждый модуль должен быть максимально самодостаточным.
	- Допустимая структура внутри модуля:
		- `jobs.py`, `exporters.py`, `config.py`, `routes.py` (если есть)
		- `templates/view.html`
		- `static/css/*.css`
		- `static/js/*.js`

- `static/`
	- Только общие стили/скрипты, которые относятся ко всему приложению.
	- Модульные стили/скрипты сюда не добавлять (кроме временной обратной совместимости).

### 2.2 Как рендерится UI

1. Пользователь открывает `/`.
2. `app.py` рендерит `templates/index.html`.
3. `index.html` подключает модульные вьюхи через `{% include ... %}`.
4. JS переключает вкладки через `data-tool-view` + `module` в query params.

Важно: это единая страница с переключаемыми блоками, а не отдельные html-страницы для каждой вкладки.

## 3) Обязательные правила при добавлении новой вкладки

## 3.1 Создать модуль в `tabs`

Пример:

```text
tabs/new_tool/
	__init__.py
	jobs.py
	exporters.py
	templates/
		view.html
	static/
		css/
			new_tool.css
		js/
			new_tool.js
```

## 3.2 Зарегистрировать модуль

- Добавить `register_module(...)` в `tabs/new_tool/__init__.py`.
- Импортировать модуль в `app.py` (как сейчас для остальных вкладок), чтобы регистрация выполнилась.

## 3.3 Подключить точку монтирования в `templates/index.html`

- Добавить include:

```jinja2
{% include 'new_tool/templates/view.html' %}
```

- Не вставлять огромный inline HTML в `index.html`; только include.

## 3.4 Подключить модульные ассеты

- CSS: подключить отдельный файл модуля.
- JS: подключить отдельный файл модуля.
- Если есть модульный static-route в `app.py`, использовать его (`/<module-slug>/static/...`).

## 3.5 Реализовать API

- Эндпоинты нового инструмента должны иметь свой префикс:
	- `/api/new-tool/job`
	- `/api/new-tool/job/<job_id>`
	- `/api/new-tool/job/<job_id>/stop`
	- `/api/new-tool/job/<job_id>/download-xlsx`

- Все защищенные эндпоинты должны быть под `@require_auth`.

## 4) Жесткие ограничения (Do / Don’t)

## Делать

- Держать бизнес-логику внутри `tabs/<module>`.
- Держать модульный UI внутри `tabs/<module>/templates` и `tabs/<module>/static`.
- Сохранять единообразные id и префиксы (`gs-*`, `ml-*`, и т.д.).
- Для localStorage использовать уникальный префикс модуля.
- Перед merge проверять импорт приложения и базовые сценарии вкладки.

## Не делать

- Не добавлять новую бизнес-логику в `templates/index.html`.
- Не копировать API другой вкладки без смены префиксов.
- Не смешивать стили разных модулей в одном модульном css.
- Не ломать существующие ключи localStorage без миграции.
- Не трогать соседние модули без явной причины.

---

## 5) Конвенции именования

- Папка модуля: `snake_case` (`google_speed`).
- URL slug модуля: `kebab-case` (`google-speed`).
- API prefix: `/api/<kebab-case>/...`.
- JS id префиксы:
	- SEO: `#...` исторические
	- Google Speed: `gs-`
	- Magic Links: `magic-links-` / `ml-`
- localStorage key: `<module>-<scope>` (пример: `google-speed-job-id`).

## 6) Чек-лист PR для новой вкладки

- [ ] Добавлен модуль в `tabs/<module>`.
- [ ] Добавлен `templates/view.html` внутри модуля.
- [ ] Добавлены `static/css` и `static/js` внутри модуля.
- [ ] Добавлен include в `templates/index.html`.
- [ ] Добавлена регистрация в `tabs/<module>/__init__.py`.
- [ ] Модуль импортируется при старте приложения.
- [ ] API endpoints имеют собственный префикс и защищены auth.
- [ ] Проверен `APP_IMPORT_OK`.
- [ ] Проверены старт/стоп/скачивание результата.
- [ ] Проверено восстановление состояния из localStorage (если используется).

## 7) Стратегия дальнейшей эволюции

Текущая целевая стратегия:

1. Сохранить `templates/index.html` как общий каркас и точку монтирования.
2. Полностью переносить содержимое вкладок в `tabs/*/templates/view.html`.
3. Полностью переносить модульные css/js в `tabs/*/static`.
4. Постепенно оставлять в корневых `templates` и `static` только общий код.

Это дает баланс:

- Не ломаем текущую работу приложения.
- Снижаем размер монолита.
- Подготавливаем проект к 10+ вкладкам.

---

## 8) Минимальная инструкция для нового разработчика

Если нужно добавить новую вкладку:

1. Скопируй структуру одного из существующих модулей в `tabs/`.
2. Сделай свой `view.html` и свои css/js в папке модуля.
3. Зарегистрируй модуль через `register_module`.
4. Подключи include в `templates/index.html`.
5. Добавь API endpoints с уникальным префиксом.
6. Прогони базовую проверку запуска и ручной smoke-test.

Если все пункты выполнены — вкладка считается корректно интегрированной.
